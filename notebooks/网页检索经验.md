# CUMCM 论文写作与分析提示词

> 用途：服务于 2026 年全国大学生数学建模竞赛的题目分析、建模讨论、代码审查和论文写作。
>
> 本文件整理了公开 GitHub 数学建模项目中常见的论文组织方式、算法表达和复核方法。它是工作辅助材料，不是官方评分标准，也不能替代当届题目、附件和论文格式规范。

### 使用这些项目时的原则

1. 先确认项目对应的年份、题目和比赛规则，再借鉴其格式。
2. 优先学习“问题如何被拆解、假设如何被验证、结论如何被限制”，不要只学习模型名称。
3. 优秀论文中的模型不一定适合本题。模型选择必须由题意、数据和约束决定。
4. GitHub 项目中的结果可能存在错误、过时规则或未经复核的经验，必须用本队数据重新验证。
5. 参考文献和资料来源要保留原始链接、作者、项目名和访问日期。

## 二、推荐论文结构

适用于大多数 CUMCM 论文，具体以当届官方格式为准。

1. 摘要
2. 关键词
3. 问题重述
4. 问题分析
5. 模型假设
6. 符号说明
7. 模型建立与求解
8. 模型检验、误差分析或灵敏度分析
9. 模型评价与推广
10. 参考文献
11. 附录：核心代码、补充证明、参数表或额外结果

### 每一部分要回答的问题

| 部分 | 需要回答的问题 |
|---|---|
| 摘要 | 解决什么问题？用了什么模型？得到什么核心结果？结论有什么实际意义？ |
| 问题重述 | 题目背景和任务是什么？输入、输出、约束分别是什么？ |
| 问题分析 | 为什么这样拆题？问题之间如何衔接？关键困难在哪里？ |
| 模型假设 | 哪些条件来自题目？哪些是队伍主动假设？假设改变会有什么影响？ |
| 符号说明 | 每个符号是否首次出现即定义？上下标、单位和范围是否统一？ |
| 模型建立 | 变量、目标函数、约束和推导是否完整？模型是否对应题意？ |
| 模型求解 | 算法输入、输出、步骤、复杂度和停止条件是什么？ |
| 模型检验 | 结果是否满足约束？是否有基准、反例、误差、敏感性或极端情形验证？ |
| 模型评价 | 优点是否有证据？缺点是否具体？适用范围和推广方向是什么？ |


```text
该问题的主要困难在于：一方面……；另一方面……。
为降低问题复杂度，本文将其分解为……、……和……三个子步骤。
```

```text
考虑到题目中的……具有……特征，本文采用……模型进行描述。
```

## 六、问题分析提示词

以下提示词可直接交给 AI、队员或用于组内讨论。使用时应把题目原文、附件、数据和当前代码一并提供。

### 1. 题意拆解

```text
请逐句阅读以下赛题，不要直接建模。先提取：
1. 已知量；
2. 未知量；
3. 决策变量；
4. 目标；
5. 硬约束；
6. 隐含约束；
7. 输出格式；
8. 题目没有给出但不能擅自假设的内容。
请对每条结论标注“题目明确给出”“由题意推导”或“需要额外假设”。
```

### 2. 题目与模型一致性

```text
请检查当前模型是否逐项对应题意。建立“题目条件—数学表达—代码实现—输出结果”四列表格。
重点检查：变量含义、单位、方向约定、边界是否包含、时间是否计入、目标函数是否遗漏、
约束方向是否写反，以及代码是否实现了论文声称的模型。
```

### 3. 假设审查

```text
请审查以下模型假设。对每条假设回答：
1. 是否来自题目；
2. 是否必要；
3. 是否可能改变结论；
4. 如何用数据或灵敏度分析验证；
5. 论文中应如何谨慎表述。
不要把队伍的方便性假设写成题目条件。
```

### 4. 建模选择

```text
请针对该问题提出三种候选模型。对每种模型说明：
变量、目标函数、约束、求解方法、优点、缺点、数据需求、可解释性和适用条件。
不要因为模型名称复杂就优先推荐，优先选择与题意最匹配且可以验证的模型。
```

### 5. 数学推导复核

```text
请逐步复核以下推导。每一步标注：
“正确”“缺少条件”“符号不一致”“维度不一致”“结论过强”或“错误”。
特别检查边界情形、零值、分母为零、角度周期、矩阵可逆性和单调性。
如果结论只在附加条件下成立，请给出准确条件。
```

### 6. 算法审查

```text
请审查算法的输入、输出、初始化、主循环、停止条件、异常处理和复杂度。
构造至少以下测试：
1. 正常小规模案例；
2. 空数据；
3. 单点或退化数据；
4. 边界值；
5. 随机案例；
6. 不满足约束的非法输入。
指出程序可能返回错误结果、崩溃或静默失败的位置。
```

### 7. 结果真实性

```text
请检查论文中的每个数值是否能由代码、数据和参数复现。
建立“结论—数据来源—脚本—随机种子—输出文件—复核方式”清单。
对于没有实验脚本或无法追溯来源的数字，标记为“不可复现”，不要直接写成确定结论。
```

### 8. 反例与边界

```text
请尝试推翻以下结论。优先构造：
1. 极端参数；
2. 对称配置；
3. 近似退化配置；
4. 空集或无界情形；
5. 随机误差方向相反的情形；
6. 最小规模和最大规模输入。
如果找不到反例，也要说明搜索范围、步长和随机种子。
```

### 9. 灵敏度分析

```text
请对参数……进行灵敏度分析。给出：
1. 参数变化范围；
2. 采样方式；
3. 评价指标；
4. 基准结果；
5. 结果变化率；
6. 稳定区间；
7. 结论适用范围。
不要只说“结果变化不大”，必须给出数值或图表依据。
```

### 10. 论文摘要

```text
请根据以下已验证结果撰写 CUMCM 风格摘要。
要求：
1. 只写已经由数据或证明支持的内容；
2. 按“背景/问题—模型—算法—核心结果—检验—结论”组织；
3. 不夸大创新性；
4. 避免“效果显著”“准确率很高”等无数据依据的词；
5. 给出 3—5 个关键词；
6. 不虚构数据、模型、实验次数和排名。
```

### 11. 论文段落润色

```text
请润色以下数学建模论文段落，保持数学含义、数字、公式和结论不变。
重点检查：
1. 术语是否准确；
2. 因果关系是否过度；
3. 题目条件与模型假设是否混淆；
4. 结论是否超过证据范围；
5. 句子是否适合正式论文；
6. 是否存在重复、空泛和口语化表达。
输出“修改后文本”和“修改原因”，不要新增未经验证的内容。
```

### 12. 论文终审

```text
请以数学建模竞赛评阅人的视角审查全文。
只列出会影响正确性、完整性、可复现性和规范性的具体问题，并按严重程度排序。
每条问题包含：
1. 位置；
2. 问题；
3. 影响；
4. 修改建议；
5. 是否需要补实验或证明。
重点检查题意对应、假设、符号、单位、公式、算法、数据来源、图表、引用、附录和 AI 声明。
```

## 七、P1 当前项目的专用提示词

### P1 模型核验

```text
请检查 P1 的“示向度误差楔形—半平面交—定位区域—直径—覆盖圆”建模链条。
逐项确认：
1. 楔形边界方向与坐标系是否一致；
2. 角度是否按正东方向逆时针定义；
3. 误差区间是否包含边界；
4. 半平面不等式方向是否正确；
5. 半平面交是否为空、退化或无界；
6. 凸多边形直径是否可由顶点对枚举得到；
7. 以直径端点为端点的圆是否用点积正确判定；
8. 目标圆域是否被纳入定位区域；
9. 每个数值是否能由 CSV 和脚本复现。
```

### P1 论文表述

```text
请将 P1 的算法写成论文中的“模型建立与求解”小节。
必须包含：符号定义、楔形集合、半平面表达、半平面交算法、
直径计算、覆盖圆判据、正确性说明、复杂度和退化情形。
明确说明定位区域是否包含半径 1800 米目标圆域。
不要把辅助计算方框描述成题目给定的目标区域。
```

### P1 数值实验

```text
请为 P1 设计可复现实验。
实验至少覆盖：不同检测点数量、交会角、检测距离、误差组合、
空集、无界、共线、对称和非对称情形。
输出随机种子、参数网格、失败定义、评价指标和结果文件。
任何“最坏情况”“失败比例”“近似误差”都必须能够从脚本重新生成。
```

## 八、常见不严谨表达及替换方式

| 不建议表达 | 建议替换 |
|---|---|
| 模型效果很好 | 在测试集/实验范围内，指标……，较基准提高…… |
| 结果非常准确 | 与……基准的误差为……，在……范围内满足要求 |
| 显然可知 | 由公式（编号）或定理……可得 |
| 证明模型完全正确 | 结果满足约束，并通过……检验；不能据此证明现实中完全正确 |
| 误差服从正态分布 | 若题目未给分布，应写“本文假设误差服从……” |
| 该算法一定最优 | 说明已证明全局最优、在候选集合中最优，或改为“得到较优解” |
| 数据表明模型稳定 | 给出参数扰动范围和结果变化率 |
| 忽略其他因素 | 明确列出忽略因素及其可能影响 |
| 取一个很大的数 | 给出数值、选取依据和对结果的影响 |
| 运行结果如图所示 | 说明图中具体趋势、比较对象和结论 |
| 具有较强推广性 | 指定可以推广到哪些条件或问题 |
| 自然得到的反例 | 说明生成机制、随机种子和复现方法 |

## 九、提交前检查清单

### 题意和模型

- [ ] 每个小问都有独立的模型、算法和结果。
- [ ] 所有题目条件都被使用或明确说明未使用原因。
- [ ] 题目条件、主动假设和实验设置没有混写。
- [ ] 目标函数、约束和输出指标的单位一致。
- [ ] 边界是否包含、角度方向和坐标系已经定义。

### 公式和证明

- [ ] 符号首次出现时已经定义。
- [ ] 公式编号、引用和上下标一致。
- [ ] 推导中的除法、开方、矩阵逆和单调性有成立条件。
- [ ] “充分”“必要”“充要”“近似”“上界”使用准确。
- [ ] 反例和紧界没有超出证明范围。

### 程序和数据

- [ ] 从干净环境可以运行。
- [ ] 路径使用相对路径。
- [ ] 随机实验固定随机种子。
- [ ] 结果可以从原始数据和脚本复现。
- [ ] 空输入、退化输入、非法输入不会静默产生错误结论。
- [ ] 图表中的数字与 CSV、论文正文一致。
- [ ] 代码中的参数与论文中的参数一致。

### 论文表达

- [ ] 摘要只包含已经验证的结果。
- [ ] 每个重要结论都有数据、证明或引用支持。
- [ ] 没有把单个算例写成普遍定理。
- [ ] 缺点和适用范围写得具体。
- [ ] 参考文献可以追溯。
- [ ] AI 工具使用声明和支撑材料符合当届规定。

## 十、重要提醒

1. 公开 GitHub 项目只能作为参考，不能替代官方题目、附件和格式规范。
2. 不要把 AI 生成的数学推导、代码和数据直接写进论文，必须人工核验。
3. 论文中最重要的不是堆砌复杂模型，而是题意对应、假设透明、推导完整、结果可复现。
4. 对未经验证的结论使用“初步结果”“数值观察”或“在本实验范围内”，不要写成无条件定理。
5. 2026 年论文格式和 AI 使用要求应以官方最新文件为准。
